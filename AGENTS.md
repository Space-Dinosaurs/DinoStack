# dinostack

A portable package of the agentic engineering protocol for AI-assisted software development. It provides a structured delegation model, risk classification, adversarial review loops, code quality gates, git workflow conventions, and named agent definitions.

## Tools
- GitHub operations: use `gh` CLI, not GitHub MCP
- `gh pr create` requires an authenticated `gh` session (`gh auth status`) - run `gh auth login` if needed.
- `rm -rf` is blocked by Claude Code permissions here; remove files individually: `rm <file>` then `rmdir <dir>`
- `bin/ds-memory` - lightweight retrieval tool for querying `.agentic/events.jsonl`, `MEMORY.md`, `.agentic/context.md` on demand.
- `bin/ds-base-sync` - fast-forwards the local base branch after a merge without a checkout; the only way to move a local branch ref outside an explicit checkout+pull.
- Force-push (`--force`, `-f`, `--force-with-lease`) is blanket-denied by the harness permission layer for subagents AND the conductor; chat authorization doesn't clear it. Push to a NEW branch name instead of rebasing a branch with an open PR.
- `bin/ds-tracker` - manages the project-local gitignored `.agentic/tracker.yml` overlay (`init`/`set`/`show`/`path`/`resolve`). Applied after the four-step `AGENTS.md` tracker chain: overlay is sole source (`_source: "overlay"`) when `AGENTS.md` declares no tracker or a different one; merges field-by-field (`_source: "merged"`) only when both declare the same tracker. Refuses git-tracked paths; `--force-unignored` overrides.
- The Graphify PyPI package is genuinely named `graphifyy` (double-y); CLI/skill command stay `graphify` - verified against upstream README, do not "fix" it.
- `git checkout <sha> -- <path>` inside a worktree resurrects files a later commit deleted (adds files present at `<sha>`, doesn't replay deletions). When basing a step on a non-`main` commit this way, `git rm` anything it deleted and gate on an exact `git ls-files` set.

## Conventions
- **Base branch:** `main` is the sole integration branch for this repo. Declaration: `BASE_BRANCH: main`.
- **Workflow for all implementation work (non-Trivial risk):**
	1. `git fetch origin` to ensure latest `main`.
	2. Spawn subagent Workers using `isolation: "worktree"` with worktrees branched from `origin/main`. Worktree path: `.agentic/worktrees/<branch-name>`.
	3. Worker implements, runs quality gates (lint, typecheck, tests), commits.
	4. Push branch to origin: `git push -u origin <branch-name>`.
	5. Open PR against `main` via `gh pr create`.
	6. Once CI/CD checks pass, auto-merge: `gh pr merge --squash --delete-branch`.
	7. Clean up: isolation worktrees are removed after push; feature worktrees after merge. Session-start prune + branch-prune remain as backstops. See `content/references/worktree-lifecycle.md` §Isolation worktree cleanup commands and §Feature worktree cleanup commands.
	8. Update local main: `bin/ds-base-sync <this-checkout-path> main` (run from this repo's own checkout, since it's both ticket repo and tool source) - fast-forwards local `main` without a checkout. Fall back to `git checkout main && git pull --ff-only origin main` only when `bin/ds-base-sync` is not present at that path.
	- Steps 6-8 are automatic - never pause for merge approval when CI is green.
	- `main` enforces strict required status checks: a PR whose base has moved must be rebased and re-run before merge - GitHub does not re-run workflows on base movement. Sync with `gh pr update-branch --rebase`; the default (merge) update produces an unsigned commit that fails the DCO check.
	- Failed CI is a hard stop - investigate before proceeding.
- **Conductor never edits shippable artifacts directly, even Trivial one-liners** - delegate to a worktree-isolated `engineer` from `origin/main`; conductor may only edit exempt artifacts (`.agentic/`, conductor-direct prints/decisions/resolver execution). Classifier: `content/rules/conventions.md` §Git Workflow.
- Superseding an open PR: close + rebase, never bundle (`content/rules/conventions.md` §Git Workflow).
- Sequential isolation:worktree spawns: the worktree is cleaned up between them, so later Workers fall back to the main tree - tell them explicitly. Round-N rework mechanic: `content/rules/conventions.md` §Git Workflow, `content/references/worktree-lifecycle.md` §Round-N rework mechanic. (DS-123)
- Parallel engineer spawn briefs must say "branch your worktree from current `origin/main`, NOT a local checkout that may include not-yet-merged sibling units" - worktree branch leaks are the most common cross-unit contamination class.
- Multi-unit PR assembly: `main` requires DCO Signed-off-by on every commit. Conductor `git merge --no-ff` is unsigned - cherry-pick each engineer's signed commit (no merge commits) or `git merge --signoff`. Never force-push to fix; `gh pr merge --admin --squash` discards merge commits anyway.
- Pre-commit does not auto-stage `.codex/agents/*.toml` - stage it manually after any `content/` edit, or extend `git add` in `hooks/pre-commit`. (`.claude/skills/dinostack/{METHODOLOGY,SKILL}.md` ARE already staged by that hook.)
- `bin/tests/` green != the gate set - required `hooks-js-tests` pins methodology prose byte-for-byte, outside `bin/tests/`. Run it after any `content/` prose edit: an inline `for f in hooks/tests/test-*.js` loop `node`-runs each file, minus files the loop's `case` arms route to `wrap-lock-tests` (currently only `test-wrap-acquire-lock.js`, `test-wrap-release-lock.js` - re-derive from `.github/workflows/hooks-tests.yml`; a "wrap-lock" filename isn't proof of membership). Prose-pinning tests: `test-wrap-md-partA-parity.js`, `test-wrap-context-format-golden.js` (sha256-pins `content/references/wrap-context-format.md`).
- **Docs-currency pass is mandatory before any work is complete/merges**, ticket or ad-hoc. Enumerate touched surfaces; fix stale docs in the SAME PR. Candidates: `docs/index.html`, `docs/slides/*.md` (rebuild via `bash scripts/build-slides.sh`), `README.md`, `CONTRIBUTING.md`, `content/SKILL.md`, relevant `AGENTS.md`. Attest with `Doc-sync:` per `content/references/doc-sync-obligation.md`.
- Any `content/{rules,references,agents,commands,sections}/` change MUST update `docs/index.html` + affected `docs/slides/*.md` (`bash scripts/build-slides.sh`, commit the regenerated `.html`, never hand-edit) in the SAME PR; also fix any now-stale count/list/ref in `README.md`, `CONTRIBUTING.md`, `content/SKILL.md`. Trigger predicate + tiering: `content/references/doc-sync-obligation.md` (Major default, Critical if misleading). `check-slides-sync` only checks deck-vs-render self-consistency - grep the decks by hand for stale-in-both content.
- Any new interactive prompt in `.claude/install.sh` MUST use `ae_confirm()` (reads `/dev/tty` when available, defaults "no"). Never bare `read -p` - it aborts under `set -euo pipefail` + piped stdin (the `curl | bash` path).
- After any `content/SKILL.md` change, run `.pi/build.sh` and `.claude/build.sh` to regenerate adapter SKILL.md copies. Pre-commit does not auto-stage these.
- Mutation-testing a `content/` spec assertion requires `bash scripts/build-all.sh` BEFORE running the test - mutating `content/` alone trips the byte-identity assertion and falsely confirms a semantic assertion caught the change.
- `codex-skill-sync` CI validates exactly 4 generated native skills under `.codex/skills/`. After changing a canonical input: `python3 scripts/codex-skills.py inventory --repo . > .codex/skill-compatibility.yml`, then `.codex/build.sh` - never hand-edit generated skill files. That redirect truncates the file to 0 bytes before Python runs, so an aborted run (e.g. a `SkillError`) leaves it empty on disk - `git checkout -- .codex/skill-compatibility.yml` restores it. Prefer a temp-file + `mv` on success, or check exit status first.
- `REPO_DIR` is distinct from `REPO`: `REPO` is the ticket's own project checkout, `REPO_DIR` is the dinostack install where `bin/`-tools live. Resolve via `scripts/lib/repo-dir.sh` (`resolve_repo_dir`): `repo_dir` from `~/.agentic/agentic-engineering-config.json` when valid, else `~/DinoStack`. `bin/ds-resolve-worktree` and `bin/ds-base-sync` both depend on it.

(`.github/skills` added DS-186.)
- Verify DCO author/sign-off with lowercase `git log --format=%ae` (raw) - uppercase `%aE` and `git show` both APPLY `.mailmap`, which can show a mismatched author email on a correctly signed commit.

- `docs/planning/` is gitignored - a worktree-isolated engineer branched from `origin/main` cannot read a plan there. Restate any obligation in the spawn brief; never keep the same binding prose in both (a fix to one copy drifts silently).
- No CI gate checks for em dashes, so scope the check to your own diff, never the whole file: `git diff --cached -U0 | grep '^+.*—'` (staged) or `git diff -U0 origin/main...HEAD | grep '^+.*—'` (branch). A whole-file grep is useless here - 13 em dashes pre-exist on `main` in the resident files (`content/rules/code-standards.md` 5, `content/sections/04-risk-classification.md` 8) and will match on every run. That count is the baseline: leave those alone, and treat any added line that matches as a defect to fix before committing - except the two in this bullet's own grep patterns, which are the literal search target and must not be "fixed" (doing so silently breaks both commands).
- A shell gate whose assertions are guarded by `command -v <tool>` must hard-fail under `${CI}` rather than skip, or the job goes green asserting nothing. `bin/tests/test_check_resident_budget.sh:155-156` is the pattern; `.github/workflows/bin-tests.yml:57-58` installs zsh so the guard never fires in CI. A silently-skipped assertion is indistinguishable from a pass in the job log.
- Editing the `main` ruleset requires the admin `gh` account - a non-admin token's read of ruleset `14778332` can return `bypass_actors` empty when the admin read returns an actor. Treat any unfetched-as-admin `bypass_actors` as unverified, not empty - a PUT built from it can wipe the entry. Back up the full ruleset JSON before any PUT and diff field-by-field after.
- Session knowledge belongs in root `MEMORY.md` (untracked, DS-129) - invisible to a worktree-isolated engineer or a fresh clone. Never end a session holding uncommitted `MEMORY.md` content that exists nowhere else - confirm with `git log --all -S "<phrase>"` plus `git stash list --all` first. Tracked `AGENTS.md` changes are a normal reviewed PR, never a session-end obligation.
- An `isolation:"worktree"` engineer spawn with a named branch can leak that branch into the conductor's own checkout and switch its HEAD (once corrupted `main`). After every worktree-isolated spawn, verify the conductor's own checkout is still on its expected branch (`git branch --show-current` + `git status` + `git diff --stat`) before committing anything from it.
- Isolation worktrees always branch from `main` HEAD, never from a named feature branch. A continuation fix for an existing feature branch can't be briefed as "branch from `origin/<feature>`" - it silently starts from main instead; cherry-pick or push the commit directly onto the existing branch's remote tip instead.
- After an isolation-worktree engineer commits, the main checkout's view of that branch ref can lag behind the worktree's own HEAD. Push the explicit commit SHA (`git push origin <sha>:refs/heads/<branch>`), not the branch name, or `gh pr create` can reject a stale-base push.
- An adapter-rebuild/baseline-regen commit (or one built from a stale local snapshot) can silently revert unrelated files with CI green - once reverted 51 files from three merged PRs; PR #390/#432 (DS-47) similarly reverted unrelated list items/counts/cross-refs. Verify a "regenerate generated artifacts" commit's diff touches *only* the intended paths; diff a PR's base..tip for unrelated hunks before merge/rebase; spot-check a key new symbol lands on `main` after a multi-PR feature, not just "merged."
- `.claude/install.sh` has a zsh variable conflict: a local variable named `status` is read-only in zsh. Avoid `status` as a variable name in zsh-specific code; run affected blocks in a bash subshell for mixed-shell compatibility.
- When `origin/main` advances mid-session, a diff against the new `origin/main` can make an unrelated, already-merged PR's files look reverted - a diff-base artifact, not a real one. Diagnose by comparing your commit's parent to `origin/main`; fix by rebasing onto current main and re-running any generator the new commits may have changed.
- Checking for duplicate in-flight work only at spawn time misses collisions starting (or merging) mid-run - two live sessions once independently fixed the same three tickets. Check open PRs and the shared checkout's `git status` before spawning, and re-check for a superseding merge right before opening a PR (a dirty `mergeStateStatus` on a fresh PR is the after-the-fact symptom). When superseded, stand down and cite the superseding PR rather than racing a rebase.
- Four git lessons: (1) flip a gitignored file to tracked via an additive negation (`!.agentic/<file>`), never remove the ignore rule; (2) a negation cannot re-include a file whose parent **directory** is excluded (`.agentic/`, `/.agentic/`, bare `.agentic` defeat `!.agentic/qa.md`) - only glob forms (`/.agentic/*`, `**/.agentic/**`) work; (3) matching is **last-match-wins** - a negation only overrides an umbrella **above** it (`bin/agentic-migrate` once appended umbrellas at EOF and killed every carve-out, fixed #527); (4) `git diff --quiet <ref> -- <path>` exits 0 for a path never committed to `<ref>` ("unchanged", not "new") - pair with `git cat-file -e <ref>:<path>` (fixed #534). Green CI per-PR doesn't guarantee `main`'s end state under concurrent sessions - assert with `git ls-files` / `git check-ignore`.
- Merging to `main` needs exactly 1 code-owner approval (`required_approving_review_count: 1`; CODEOWNERS: `* @tysonhummel`). `--admin` is required for `gh pr merge` when authored by @tysonhummel (self-approval disallowed) or no `@tysonhummel` reviewer present. An approval-required `--admin` failure means the bypass actor was removed - re-add via GitHub UI.
- The live Claude Code harness auto-locks every `isolation:"worktree"` worktree at creation.
