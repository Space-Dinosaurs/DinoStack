# dinostack

A portable package of the agentic engineering protocol for AI-assisted software development. It provides a structured delegation model, risk classification, adversarial review loops, code quality gates, git workflow conventions, and named agent definitions.

- Per-PR delta axis on the two shared/merge-order-sensitive budget gates (DS-182): `budget_report`'s pre-DS-182 shape (prints OK/OVER BUDGET and `exit`s itself) is unchanged for its one remaining original caller, `check-resident-budget.sh` (byte-unchanged; it gained no git axis at all) - `scripts/lib/budget-gate.sh` split its body into a non-exiting `budget_eval` (returns 0/1) plus a thin `budget_report` wrapper (`if budget_eval "$@"; then exit 0; else exit 1; fi`). New library functions `budget_base_resolve <repo_dir> [base_branch]` (resolves `origin/<branch>` then `<branch>` against `-C <repo_dir>`, default `main`; returns 1 and prints nothing when git/a work tree/a resolvable ref is unavailable - takes `repo_dir` explicitly, same as `budget_delta`, so both always resolve against the caller's repo root rather than the process's own cwd), `budget_delta` (signed byte delta of a path between a base ref and the working tree; returns 2 and prints nothing when the path is absent at base - never conflated with a delta equal to the path's own full size), and `budget_burn_line` (one informational line, ALWAYS returns 0 and ALWAYS prints something - a distinct "burn: SKIPPED (...)" line, never a blank line, when git/a base ref/the base commit date is unavailable). Two different uses on the two gates that needed a git axis: `check-command-file-budget.sh` (hand-authored file - a PR's diff to it is that PR's own doing) gained a hard-failing per-PR `DELTA_LIMIT_BYTES` (32,936 B, re-derived as `ceil(max_observed_delta * 1.1)` from the 43 first-parent non-creation commits touching the file, `max_observed_delta = 29,941 B` at commit `d644217c`; fires 0/43 on the history it was derived from) - it calls `budget_eval` directly (not `budget_report`), since a delta breach is recorded (`delta_over=1`) rather than exiting immediately, so the `THRESHOLD_BYTES` `budget_eval` report still runs and prints even when both axes are over budget in the same run; the delta context is reported via `budget_eval`'s existing extra-context slot so `lines[-1]` of stdout (what `bin/ds-evaluate`'s `_collect_budget_gates` reads as the gate's summary) stays the `headroom:` line. `check-skill-embed-budget.sh` (a GENERATED artifact - its size on any branch reflects upstream `content/**` churn as much as that PR's own diff, the exact "merge order decides pass/fail" failure mode DS-182 exists to close, per KNW-20260818-001) gained only the informational `budget_burn_line` (a B/day burn RATE, `"burn: <B_per_day> B/day over <D> d - <N> d to limit"`, not a raw delta - `<D>` is the whole-day span since the resolved base ref's own commit date, floored at 1; `<N>` = headroom / burn rate, omitted when the rate is <= 0), no hard delta limit. Its OK-path tail is hand-rolled directly in the gate script rather than routed through `budget_eval`, because `bin/ds-evaluate`'s summary consumer depends on the exact pre-DS-182 wording (`ceiling:`/`headroom to ceiling:`), which `budget_eval`'s shared `threshold:`/`headroom:` labels cannot express; the burn line is computed once before the FLOOR/CEILING checks and printed on all three exit paths (OK, BELOW FLOOR, ABOVE CEILING), not only the OK path. Both workflow files needed `fetch-depth: 0` added to the relevant checkout step(s) (`command-file-budget.yml`'s single job; `resident-budget.yml`'s `check-skill-embed-budget` job only - `check-resident-budget`'s checkout is deliberately untouched, since that gate gained no git axis at all) or `origin/main` is unreachable on a default shallow checkout and the git axis silently degrades to its SKIPPED variant on every CI run. All three git-based functions degrade gracefully (never a hard failure) when git is absent or `repo_dir` isn't a git work tree - verified against every per-gate test suite (`grep -rl budget-gate.sh bin/tests/test_check_*.sh` finds the current set - `test_budget_gate_lib.sh` is a sibling library-level suite outside this set and does build a real `git init` fixture for its own DS-182 scenarios), which have always built their scratch fixtures with zero `git init` at all. Deciding which axis a NEW budget-gate target needs (a hard per-PR `DELTA_LIMIT_BYTES` for an AUTHORED/hand-edited target, vs. an informational `budget_burn_line` for a DERIVED/generated one) is not a fresh judgment call each time: run `bash scripts/gate-provenance.sh <repo-relative-path>` first - it classifies the target as `AUTHORED` or `DERIVED` against the real CI workflows and manifest headers and cites which rule fired. DS-183/184/185/186 (any future budget-gate axis work) should run it before assigning an axis, not re-derive the classification by hand.

## Tools
- GitHub operations: use `gh` CLI, not GitHub MCP
- `gh pr create` requires an authenticated `gh` session (`gh auth status`) - run `gh auth login` if needed.
- `rm -rf` is blocked by Claude Code permissions here; remove files individually: `rm <file>` then `rmdir <dir>`
- `bin/ds-memory` - lightweight retrieval tool for querying `.agentic/events.jsonl`, `MEMORY.md`, `.agentic/context.md` on demand.
- `bin/ds-base-sync` - fast-forwards the local base branch after a merge without a checkout; the only way to move a local branch ref outside an explicit checkout+pull.
- Force-push (`--force`, `-f`, `--force-with-lease`) is blanket-denied by the harness permission layer for subagents AND the conductor; chat authorization doesn't clear it. Push to a NEW branch name instead of rebasing a branch with an open PR.
- `bin/ds-tracker` - manages the project-local gitignored `.agentic/tracker.yml` overlay (`init`/`set`/`show`/`path`/`resolve`). Applied after the four-step `AGENTS.md` tracker chain: overlay is sole source (`_source: "overlay"`) when `AGENTS.md` declares no tracker or a different one; merges field-by-field (`_source: "merged"`) only when both declare the same tracker. Refuses git-tracked paths; `--force-unignored` overrides.
- The Graphify PyPI package is genuinely named `graphifyy` (double-y); CLI/skill command stay `graphify` - verified against upstream README, do not "fix" it.
- `git checkout <sha> -- <path>` inside a worktree resurrects files a later commit deleted (adds files present at `<sha>`, doesn't replay deletions). When basing a step on a non-`main` commit this way, `git rm` anything it deleted and gate on an exact `git ls-files` set.

## Conventions
- **Base branch:** `main` is the sole integration branch for this repo. Declaration: `BASE_BRANCH: main`.
- **Workflow for all implementation work (non-Trivial risk):**
	1. `git fetch origin` to ensure latest `main`.
	2. Spawn subagent Workers using `isolation: "worktree"` with worktrees branched from `origin/main`. Worktree path: `.agentic/worktrees/<branch-name>`.
	3. Worker implements, runs quality gates (lint, typecheck, tests), commits.
	4. Push branch to origin: `git push -u origin <branch-name>`.
	5. Open PR against `main` via `gh pr create`.
	6. Once CI/CD checks pass, auto-merge: `gh pr merge --squash --delete-branch`.
	7. Clean up: isolation worktrees are removed after push; feature worktrees after merge. Session-start prune + branch-prune remain as backstops. See `content/references/worktree-lifecycle.md` §Isolation worktree cleanup commands and §Feature worktree cleanup commands.
	8. Update local main: `bin/ds-base-sync <this-checkout-path> main` (run from this repo's own checkout, since it's both ticket repo and tool source) - fast-forwards local `main` without a checkout. Fall back to `git checkout main && git pull --ff-only origin main` only when `bin/ds-base-sync` is not present at that path.
	- Steps 6-8 are automatic - never pause for merge approval when CI is green.
	- `main` enforces strict required status checks: a PR whose base has moved must be rebased and re-run before merge - GitHub does not re-run workflows on base movement. Sync with `gh pr update-branch --rebase`; the default (merge) update produces an unsigned commit that fails the DCO check.
	- Failed CI is a hard stop - investigate before proceeding.
- **Conductor never edits shippable artifacts directly, even Trivial one-liners** - delegate to a worktree-isolated `engineer` from `origin/main`; conductor may only edit exempt artifacts (`.agentic/`, conductor-direct prints/decisions/resolver execution). Classifier: `content/rules/conventions.md` §Git Workflow.
- Superseding an open PR: close + rebase, never bundle (`content/rules/conventions.md` §Git Workflow).
- Sequential isolation:worktree spawns: the worktree is cleaned up between them, so later Workers fall back to the main tree - tell them explicitly. Round-N rework mechanic: `content/rules/conventions.md` §Git Workflow, `content/references/worktree-lifecycle.md` §Round-N rework mechanic. (DS-123)
- Parallel engineer spawn briefs must say "branch your worktree from current `origin/main`, NOT a local checkout that may include not-yet-merged sibling units" - worktree branch leaks are the most common cross-unit contamination class.
- Multi-unit PR assembly: `main` requires DCO Signed-off-by on every commit. Conductor `git merge --no-ff` is unsigned - cherry-pick each engineer's signed commit (no merge commits) or `git merge --signoff`. Never force-push to fix; `gh pr merge --admin --squash` discards merge commits anyway.
- Pre-commit does not auto-stage `.codex/agents/*.toml` - stage it manually after any `content/` edit, or extend `git add` in `hooks/pre-commit`. (`.claude/skills/dinostack/{METHODOLOGY,SKILL}.md` ARE already staged by that hook.)
- A green `bin/tests/` run is not the gate set - the required `hooks-js-tests` check pins methodology prose byte-for-byte and lives outside `bin/tests/`. After any `content/` prose edit, run the hooks JS suite too. It has no single literal command: the job is an inline `for f in hooks/tests/test-*.js` loop that `node`-runs each file, minus whichever files the loop's own `case` arms quarantine into the separate `wrap-lock-tests` job (currently `test-wrap-acquire-lock.js` and `test-wrap-release-lock.js` - re-derive from the case arms in `.github/workflows/hooks-tests.yml`, don't hand-count the glob; a filename containing "wrap-lock" is not by itself evidence of membership - e.g. `test-wrap-lock-abandoned.js`, `test-wrap-lock-session-id.js`, and `test-wrap-lock-verdict.js` all run in `hooks-js-tests`, not `wrap-lock-tests`). Two of those prose-pinning tests are `test-wrap-md-partA-parity.js` (asserts `/ds-wrap` retains its whole-flow lock) and `test-wrap-context-format-golden.js` (sha256-pins `content/references/wrap-context-format.md` from its NORMATIVE marker to EOF).
- **Docs-currency pass is mandatory before any work is declared complete and before its PR merges** - ticket work or ad-hoc, regardless of which paths changed. Enumerate the surfaces the diff touched, then verify and update any related documentation that now states something stale; land doc updates in the SAME PR as the work. Candidate doc surfaces to check: `docs/index.html`, `docs/slides/*.md` (plus rebuilt `.html` via `bash scripts/build-slides.sh`), `README.md`, `CONTRIBUTING.md`, `content/SKILL.md`, and the relevant `AGENTS.md` sections. This generalizes the `content/`-triggered bullet below: that bullet's trigger stays mandatory for `content/` edits specifically, while this pass applies to all work. Record the pass's outcome with the canonical `Doc-sync:` attestation from `content/references/doc-sync-obligation.md` - either `Doc-sync: predicate not triggered (no reality-asserting change).` or the triggered/updated form. Skeptic tiering per `content/references/doc-sync-obligation.md`.
- Any change to `content/rules/`, `content/references/`, `content/agents/`, `content/commands/`, or `content/sections/` MUST also update `docs/index.html` and any affected `docs/slides/*.md` (then run `bash scripts/build-slides.sh` and commit the regenerated `.html` - do not hand-edit the `.html`; upgrading marp is an intentional same-PR action: bump `scripts/package.json` + regenerate `scripts/package-lock.json` + rebuild) in the same PR; additionally, any now-stale count, list, or reference in `README.md`, `CONTRIBUTING.md`, or `content/SKILL.md` is in-scope for the same PR. - Four git lessons: (1) flip a gitignored file to tracked via an additive negation (`!.agentic/<file>`), never remove the ignore rule; (2) a negation cannot re-include a file whose parent **directory** is excluded (`.agentic/`, `/.agentic/`, bare `.agentic` defeat `!.agentic/qa.md`) - only glob forms (`/.agentic/*`, `**/.agentic/**`) work; (3) matching is **last-match-wins** - a negation only overrides an umbrella **above** it (`bin/agentic-migrate` once appended umbrellas at EOF and killed every carve-out, fixed #527); (4) `git diff --quiet <ref> -- <path>` exits 0 for a path never committed to `<ref>` ("unchanged", not "new") - pair with `git cat-file -e <ref>:<path>` (fixed #534).
