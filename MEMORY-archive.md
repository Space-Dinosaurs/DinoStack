## Worktree & Git Hygiene

- **2026-06-12: An `isolation:"worktree"` engineer spawn with a named branch can leak that branch into the conductor's own checkout and switch its HEAD.** Observed corrupting `main` once (a subsequent conductor commit captured the diverted state as mass deletions). After every worktree-isolated spawn, verify the conductor's own checkout is still on its expected branch (`git branch --show-current` + `git status` + `git diff --stat`) before committing anything from it.

- **2026-07-08: Isolation worktrees always branch from `main` HEAD, never from a named feature branch.** A continuation fix meant to land on an existing feature branch can't be briefed as "branch your worktree from `origin/<feature>`" - it will silently start from main instead. The fix has to cherry-pick or push its commit directly onto the existing branch's remote tip, not attempt to branch from it.

- **2026-06-12: `git checkout <sha> -- <path>` inside a worktree resurrects files a later commit deleted.** It updates/adds files present at `<sha>` but does not replay deletions, so files removed downstream of that commit silently reappear (they were never gone from the worktree's disk - it started from `main`). When basing a step on a non-`main` commit this way, explicitly `git rm` anything that commit deleted, and gate on an exact `git ls-files` set rather than trusting the chain.

- **2026-06-29: After an isolation-worktree engineer commits, the main checkout's view of that branch ref can lag behind the worktree's own HEAD.** Pushing by branch name can ship the stale base commit and `gh pr create` will reject it ("no commits between main and branch"). Push the explicit commit SHA (`git push origin <sha>:refs/heads/<branch>`), not the branch name.

- **2026-06-04: An adapter-rebuild/baseline-regen engineer commit can silently revert unrelated source files, and green CI will not catch it.** A stale isolation worktree once produced a commit that reverted 51 files from three already-merged PRs while the adapter/baseline outputs stayed internally consistent - every sync gate passed. Verify any "regenerate generated artifacts" commit's diff touches *only* the intended generated paths before merging; after any multi-PR feature lands, spot-check that a key new symbol is actually present on `main`, not just that the PRs show "merged."

- **2026-07-09: The 2026-06-04 "silent revert" failure mode also occurs from a hand-authored feature commit, not just a regen commit.** A PR's original commit, authored from a stale local snapshot, silently reverted unrelated content (list items, counts, cross-refs) in files it legitimately touched; green CI did not catch it and a plain rebase would have shipped the drops. Diff the PR's base..tip for hunks unrelated to its stated intent before merging or rebasing (PR #390/#432, DS-47).

- **2026-07-08: When `origin/main` advances mid-session, a diff against the new `origin/main` can make an unrelated, already-merged PR's files look reverted.** This is a diff-base artifact, not a real revert: your branch predates that merge. Diagnose by comparing your commit's parent to `origin/main`; fix by rebasing onto current main and re-running any generator the newly-merged commits may have changed (adapters, baselines, slides).

- **2026-07-02: Checking for duplicate in-flight work only at spawn time misses collisions that start (or merge) while a worker is running.** Two live sessions once independently fixed the same three tickets; check open PRs and the shared checkout's `git status` before spawning, and re-check for a superseding merge right before opening a PR (a dirty `mergeStateStatus` on a fresh PR is the after-the-fact symptom). When superseded, stand down and cite the superseding PR rather than racing a rebase.

- **2026-06-13: Two reusable git lessons from consolidating knowledge-capture routing.** (1) To flip a gitignored file to tracked, append a negation line (`!.agentic/<file>`) rather than removing the ignore rule - removal is the fail-open/leak direction and was flagged as a secret-exposure vector in a security review; additive negation is monotonic and safe. (2) A per-PR green CI does not guarantee the end state on `main` is correct when multiple sessions touch it concurrently - a later, unrelated PR silently clobbered a just-merged file and its gitignore carve-out. After multiple sessions land work on `main`, assert the end state directly (`git ls-files`, `git check-ignore`) rather than trusting each PR's own green check.

- **2026-06-16: Merging to `main` requires `gh pr merge --squash --delete-branch --admin`.** The branch-protection ruleset requires 3 approving reviews plus last-push-approval, which a solo pusher can never satisfy normally; Repository Admin is the ruleset's bypass actor. If `--admin` ever starts failing with an approval-required error, the bypass actor was removed from the ruleset and needs to be re-added in GitHub's UI (a standard PAT cannot patch rulesets via the API).

- **2026-07-14: The live Claude Code harness auto-locks every `isolation:"worktree"` worktree at creation.** Directory is `.claude/worktrees/agent-<agentId>` (note: NOT `worktree-agent-<id>` - that's the branch name), branch is `worktree-agent-<agentId>`, and `git worktree list --porcelain` shows `locked claude agent agent-<agentId> (pid <pid> ...)`; a non-force `git worktree remove` already refuses it (`remove -f -f` needed), independent of any methodology-level lock. Any worktree-cleanup detection logic must match the branch-name pattern, not assume the directory path contains the same substring.

## Hooks & Subagent Mechanics

- **2026-07-08: PreToolUse hook mechanics for Agent/Task spawns.** `tool_input` on a spawn call exposes `subagent_type`, `prompt`, `description`, and `model` (absent - not null - when the spawner omitted it); subagent model resolution precedence is `CLAUDE_CODE_SUBAGENT_MODEL` env > spawn-call `model` param > agent frontmatter `model:` > inherited session model, so a hook gating on `tool_input.model` sees the conductor's stated intent, not an env override. To deny a spawn: print `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}` and exit 0. To **warn without blocking** (e.g., an advisory nudge), use `"permissionDecision":"allow"` with a `permissionDecisionReason` - this surfaces text to the model without a human prompt and without denying; it's the mechanism behind the planning-artifact advisory hook.

- **2026-06-30: An LLM cannot reliably run a long foreground poll loop (foreground `sleep` is blocked in the harness).** `/wrap`'s lock-wait used to be prose the conductor hand-ran ("poll every 5s for 20min") and reliably gave up after one or two checks. Fix pattern: move the poll loop into a small binary invoked as a **background** spawn (`run_in_background: true`) so the conductor stays available and gets notified with an exit code on completion - a background spawn on this harness does deliver a synchronous exit code on completion, contrary to an earlier assumption.

- **On a GLM session (or any non-Claude model backing the session), spawning a methodology subagent (engineer, skeptic, etc.) fails immediately.** Every agent's frontmatter `model:` is a Claude alias that resolves to a `claude-*` model ID the non-Claude key doesn't carry, and the Agent tool's `model` param enum is Claude-only - there is no way to route a subagent to a non-Claude backend. On such a session, don't attempt Worker/Skeptic delegation; go conductor-direct and compensate with mechanical verification, or switch the session to a Claude model first.

- **2026-06-25: AE agents carry an explicit `model:` in frontmatter (opus for `skeptic`/`security-auditor`, sonnet for the rest).** Omit the spawn-call `model` param to accept an agent's role default; pass it explicitly only to override a specific spawn (e.g., escalating a Tier-2 agent to Opus for a mandated-Tier-3 review, or documenting a Tier-3 mandate explicitly even though frontmatter would already resolve it correctly). Passing a param unconditionally on every spawn defeats the point of the frontmatter defaults - it silently overrides Opus on review agents.
