## Project Conventions

- **2026-04-28:** This project uses `main` as the sole integration branch. Do not use `develop`/`development` branching model for this repository - all feature/fix/chore work branches from `main` and merges back to `main`.

- **2026-07-02: `bin/*` CLIs that load `_lib.py` are broken when invoked via their PATH symlink - use `Path(__file__).resolve().parent`, never `.parent`.** `install.sh` symlinks `bin/agentic-*` into `~/.local/bin` but NOT `_lib.py`; the loader shim `Path(__file__).parent / "_lib.py"` then resolves to `~/.local/bin/_lib.py` (missing) because `__file__` is the symlink path -> `FileNotFoundError`. Masked everywhere because all call sites soft-fail (`2>/dev/null || true`), so identity/telemetry have been latently non-functional through bare-command invocation. Fix: `Path(__file__).resolve().parent / "_lib.py"` (follows the symlink to the real repo `bin/`; no-op when not symlinked). `bin/agentic-feedback` is the reference for the correct pattern (fixed in DS-56); every OTHER `_lib`-dependent bin still has the bug - tracked in DS-66. Regression guard: invoke the CLI through a real `os.symlink` via subprocess in the test, not just in-process import.

- **2026-07-08: Empty bash array + `set -u` aborts on macOS bash 3.2 — the dormant-install regression.** Adapter `install.sh` scripts run `set -euo pipefail` and collect `--dormant/--resident` into `AE_DORMANCY_ARGS=()`. Expanding an EMPTY array with the bare `"${AE_DORMANCY_ARGS[@]}"` under `nounset` raises `unbound variable` on `/bin/bash` 3.2 (macOS default) — it does NOT on bash 4+/5 (Linux CI, dev machines with newer bash), so CI stays green while real macOS `curl | bash` installs crash the moment no dormancy flag is passed (the common case). Fix: `"${AE_DORMANCY_ARGS[@]:-}"` (yields one empty-string arg; `ae_resolve_dormancy`'s `case "$arg"` loop ignores it → resolves `resident` back-compat). Hit in claude/codex/gemini/kimi/opencode/pi/omp/hermes/copilot (all `AE_DORMANCY_ARGS` consumers). Reproduce the gap with `/bin/bash -uc 'a=(); f(){ :; }; f "${a[@]}"'` (fails 3.2, passes 5). Same trap applies to ANY empty-array expansion under `set -u` in adapter scripts. `bin/tests/test_activation.sh` has a regression assertion for it.

- **2026-07-08: Testing an adapter `install.sh` with a fake `$HOME` LEAKS to the real config dir when a `*_CODING_AGENT_DIR` / `AGENTIC_CONFIG_DIR` env var is set.** `.pi/install.sh` resolves its target as `PI_CONFIG_DIR="${AE_CONFIG_DIR_FLAG:-${AGENTIC_CONFIG_DIR:-${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}}}"` — so a fake `HOME=$(mktemp -d)` is silently overridden if `PI_CODING_AGENT_DIR` (or the equivalent for another harness) is exported in the tester's shell, and the install writes into the REAL dir. This produced a false-negative "stub not written" during Unit 11 QA (the stub WAS written, just to `~/.pi-solara6/agent` not the sandbox). When hermetically testing an adapter install, `env -u PI_CODING_AGENT_DIR -u AGENTIC_CONFIG_DIR` (and any sibling `*_CODING_AGENT_DIR`) alongside the fake `HOME`, or pass `--config-dir=<sandbox>` explicitly.

- **2026-06-11: Dark-theme reskin gotcha — Marp `theme: default` leaks high-specificity light styles.** The 15 `*-slides.md` decks were reskinned to the DinoStack "Iridium" dark look (palette/fonts sourced from `docs/index.html`: `#02050C` canvas + cyan/violet radial aura, Orbitron headings, Nunito Sans body, JetBrains Mono code, `#18E0FF` primary). Two non-obvious traps when overriding Marp's default theme via the inline `style:` block: (1) **Table rows render white** — Marp's `section table tr { background: var(--bgColor-default) }` (white) out-specifies a bare `tr` selector. Fix: match its shape exactly — `table tr { background: transparent }` + `table tr:nth-child(2n) { background: rgba(255,255,255,0.03) }`. (2) **Syntax-highlighted code is dark-on-dark** — language-tagged fences (```yaml/json/bash) get highlight.js tokens whose GitHub-theme vars stay in their light branch because `section` keeps `color-scheme: light`. Fix: add `color-scheme: dark` to the `section` rule (flips all `--color-prettylights-syntax-*` to their legible dark-mode values). Plain ``` fences have no tokens, so screenshot a *highlighted* code slide when QA-ing. Edit the `.md` only, then regenerate via `bash scripts/build-slides.sh` (idempotent; `slides-sync.yml` CI gate enforces .md↔.html sync). Canonical Iridium base block now lives identically in all 15 decks' frontmatter.
