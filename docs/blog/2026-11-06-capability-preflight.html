Capability preflight: checking an agent's tools before it starts

2026-11-06

An agent that finds out partway through a task that a tool it needs is missing has spent the run getting there. DinoStack moves that discovery to the start. Before every agent spawn, the conductor reads the target agent's capabilities: block, if it has one, and checks that the tools it declares for this particular task are available in the current environment.

A manifest in each agent

An agent definition under content/agents/ may carry a capabilities: block with required and optional entries. Each entry names a tool and a check, a POSIX shell command that exits 0 when the tool is present. It can also carry an install command, a human-readable install_hint, an auto_install flag, and a required_when predicate. An agent with no block at all is a complete no-op, which keeps adoption incremental: an agent that has not declared a manifest is never blocked.

Required only when the task needs it

A QA agent does not need an accessibility engine for every job, so a requirement can be conditional. required_when is a small fixed grammar, with no arbitrary code: scenario.method == 'X', scenario.method in ['X', 'Y'], and brief.has_field('name'), joined with && and ||. The scenario predicates read the spawn's qa_criteria. When the predicate is false for a spawn, the entry is downgraded to optional, warn-on-miss, for that spawn only. A spawn with no Brief evaluates every brief.has_field() as false.

The qa-engineer manifest shows the pattern. @axe-core/playwright is required only for an accessibility scenario, pixelmatch and pngjs only for perceptual_diff, and playwright-python only for motion. agent-browser, chrome-devtools-mcp and a running Storybook server are optional.

Safe auto-install, and nothing else

auto_install: true is restricted to commands whose only side effect is changing the project's node_modules/, ~/.local/, or pip --user site-packages: npm install --no-save <pkg> and pip install --user <pkg>. It is forbidden for anything that downloads browser binaries (such as playwright install chromium, about 150MB), global npm installs, anything needing sudo, and anything that changes package.json, a lockfile, requirements.txt or pyproject.toml. Those use install_hint instead, which is shown to you as an action item and never run automatically.

The flow

For an agent with a manifest, the preflight resolves each required_when against the spawn, runs each check, auto-installs safe misses and re-checks them, then reports what is still missing. Hits are cached in .agentic/.capability-cache.json for 30 minutes. Misses are never cached, so a tool you install mid-session is picked up on the next spawn with no cache to clear. When anything is missing, the report names the agent, the mode, and each missing tool with its install command or hint. The reference's own example:

  • qa-engineer preflight: blocking
  • required missing: @axe-core/playwright, install: npm install --no-save @axe-core/playwright
  • optional missing: agent-browser, install: npm install -g agent-browser

A clean check prints nothing.

Blocking by default

The mode is capability_preflight_mode in .agentic/config.json. In advisory mode the conductor warns, naming the agent, the tool and the install command, then spawns anyway. In blocking mode it refuses the spawn when a required tool is still missing after auto-install. blocking is the default, and any missing or unrecognized value falls back to it. Projects seeded before blocking became the default, with advisory in their config, keep that value.

Caveats

  • Checks must be POSIX /bin/sh commands. Windows users run through WSL or Git Bash; a check written in PowerShell syntax fails silently and counts as a miss.
  • The preflight is a procedure the conductor follows, written down in the methodology; its reference describes itself as prose that does not execute.
  • It covers only what an agent's manifest declares. A tool nobody listed is never checked.

Why it matters

A missing tool is cheapest to find before an agent starts. The preflight makes each agent's needs explicit, scales them to the task, installs only what is safe to install without asking, and by default stops a spawn that would fail for lack of a tool, with the command that fixes it.
