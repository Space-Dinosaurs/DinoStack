One conversation, many tickets: DinoStack's conductor and lanes

2026-11-06

Running several tickets at once usually means several terminal windows, each waiting on you. DinoStack's conductor and lanes turn that into one conversation. You talk to a single conductor session. It starts each ticket as its own headless session, watches them, and comes back to you only when one of them needs a decision.

The conductor

The conductor starts from a /ds-ticket-triage plan, which analyses the tickets' dependencies and conflicts and splits them into parallel lanes. From there the conductor:

  • starts each lane and watches all of them,
  • relays your rulings to the lanes they concern,
  • surfaces a blocked or failed lane to you as a decision, and holds risky actions until you rule,
  • re-runs triage over the remaining tickets when a wave is done, and presents the next wave.

It does no ticket work itself. Its state lives in one file, .agentic/runbook-<KEY>.json, which it reads first after a context compaction, so a long run survives one. And no message from the conductor ever tells a lane to skip its own Skeptic review, QA, or gates.

Lanes

ds-lane starts each lane as its own headless Claude Code or Codex session, picking the harness the conductor itself is running in. Up to 5 lanes run at once per repo by default (DS_LANE_MAX); the rest queue and start as slots free up. Each lane ends its work with a LANE-DONE or LANE-BLOCKED marker. A lane stopped by a usage limit shows as blocked with the reset time, and resumes later in the exact session it left.

Each lane runs the ticket workflow, scaled to risk

A lane is not a single worker. Each one runs /ds-implement-ticket, which picks its route from the ticket's risk class:

  • Every route: an engineer working in an isolated worktree, the project's quality checks, and a PR, which can merge on its own once CI passes when auto-merge is turned on.
  • Trivial: one engineer; no Skeptic review and no QA.
  • Low: no Skeptic review; QA runs when the change is user-visible UI.
  • Elevated: an adversarial Skeptic review loop with a round cap, plus QA where the project's QA gate applies.

Running tickets in parallel does not lower that bar: no message from the conductor ever tells a lane to skip its own Skeptic review, QA, or gates.

Design choices

  • Lanes don't talk to each other. Every message goes through the conductor, which delivers it with ds-lane send or ds-lane resume.
  • Each lane opens its own PR. There is no separate merge step to coordinate.
  • Stalls are caught mechanically. The conductor runs ds-lane wait, which returns as soon as a lane finishes, blocks, or dies, with a 30-minute cron as a backstop, rather than asking a model to judge whether a lane looks stuck.

The lane lifecycle

The conductor watches its lanes with ds-lane wait, which returns as soon as a lane finishes, blocks, or dies, and a 30-minute cron is the backstop. A finished lane frees its slot and the next queued lane starts. A blocked or dead lane becomes a decision for you, and your ruling goes back to the same session.
