One methodology, eleven harnesses: DinoStack's adapters

2026-11-06

DinoStack is not tied to one AI coding tool. The same methodology is packaged for 11 of them, and each gets an adapter directory that turns the shared source into that tool's own formats. If your team runs more than one harness, they can share one set of rules, agents and commands.

The eleven adapters

  • Claude Code, in .claude/
  • Cursor, in .cursor/
  • Codex CLI, in .codex/
  • Gemini CLI, in .gemini/
  • Kimi Code CLI, in .kimi/
  • OpenCode, in .opencode/
  • Pi coding agent, in .pi/
  • Pi (oh-my-pi), in .omp/
  • Hermes Agent, in .hermes/
  • OpenClaw, in .openclaw/
  • VS Code Copilot, in .copilot/, plus Copilot surfaces under .github/

Every one of these directories has its own build.sh, install.sh, uninstall.sh and README.md with setup instructions.

One source, many formats

The methodology lives once, in content/, and is single-sourced into every adapter directory; scripts/build-methodology.sh is the canonical script that assembles it. Some adapter files are generated, and some link straight into content/. The output still differs by tool where the tool needs it. Cursor's build has a different output structure and skips the shared assembly script. Codex installs exactly four native skills, dinostack-codex plus brief, wrap and implement-ticket variants, under their own names because Gemini also reads the shared ~/.agents/skills/ directory; you invoke them as $dinostack-codex-brief and so on, not /ds-brief. And some files in the adapter directories, such as several adapters' hook files, are hand-authored and not regenerated by any build.

Claude Code first

Eleven adapters means eleven sets of generated files, so the project picked an order. Since an operator ruling at the end of October 2026, Claude Code is the primary harness: a methodology PR regenerates and checks only .claude/, with bash .claude/build.sh, and CI always checks that adapter for drift. The other 10 adapters, plus the .github/ Copilot surfaces, catch up later in one on-demand chore PR, never in each PR.

Everything that builds or checks them is off by default and comes back with one switch, DS_ALL_HARNESSES=1. It turns back on the pre-commit hook's non-Claude builds and staging, the Codex skill-sync gate, the build and drift checks in scripts/check-local.sh, and the tests that read or rebuild non-Claude output. In CI it is set for any PR whose branch starts with chore/adapter-catch-up. As part of the same change, the Codex skill-sync check left the set of checks required to merge; it now runs on PRs that touch the Codex skill pipeline, or on demand.

The trade-off, stated plainly

Between catch-ups, main carries non-Claude generated files that lag content/. If you use one of those adapters, here is what that means:

  • Outside DS_ALL_HARNESSES=1, the non-Claude installers do not run their build. They install the committed files, so your checkout stays clean and ds-update keeps working.
  • You get a mix: files the adapter links straight into content/ are current, generated files are as old as the last catch-up, and a link to a content/ file that was renamed or deleted since then dangles until the next one.
  • The Codex installer warns when its source is stale, or when its staged build failed, and installs the committed files.
  • To build and install a non-Claude adapter from current content/, run its installer with DS_ALL_HARNESSES=1. That dirties your checkout until the catch-up merges.

If ds-update later stops because the working tree has uncommitted changes, and every listed path is under the non-Claude adapter directories, those are rebuilt artifacts. CONTRIBUTING.md gives the commands to check that none of them are your own edits, discard them, and re-run.

The catch-up

The catch-up chore is a short, documented procedure: branch chore/adapter-catch-up-<date> from origin/main, regenerate the Codex skill inventory, run bash scripts/build-all.sh, commit the non-Claude adapter directories and the .github/ Copilot paths with a signed commit, then run DS_ALL_HARNESSES=1 bash scripts/check-local.sh and the Codex skill tests before opening the PR.

Why it matters

DinoStack keeps one source for every harness, and is explicit about the cost of maintaining eleven: Claude Code gets every change immediately, the others get them in batches, and the docs say exactly what you are running in between.
