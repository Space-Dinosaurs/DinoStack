Worktree-isolated engineers: why the conductor never edits shippable files

2026-11-06

In DinoStack the main session agent is a conductor, not an implementer. It decomposes the work, delegates it to specialist subagents, and synthesizes what they report, staying available to you the whole time. One rule makes that division concrete: the conductor never edits shippable files directly, not even for a Trivial one-line change. Every shippable change goes to an engineer working in its own git worktree, branched from origin/main.

What counts as shippable

"Shippable" is decided by a four-rule classifier, and the first match wins:

  • Anything under .agentic/ is exempt; the conductor is its sole writer.
  • Anything under docs/planning/ is exempt: Briefs, Plans and ADRs. Every other doc is shippable, by name.
  • A conductor-direct print, decision or resolver run is exempt.
  • Any other write to a tracked file is shippable, and is delegated to a worktree-isolated engineer: with no Skeptic and no brief for a Trivial change, with the full Worker and Skeptic loop for an Elevated one.

A hook backs the rule

On Claude Code, hooks/enforce-shippable-edit.py turns this prose into a hard gate inside the DinoStack checkout. It runs before every Write, Edit and MultiEdit and denies one issued directly by the conductor against a shippable file in the repo, while allowing the same edit from an engineer subagent. It has stated limits. The instruction-layer files AGENTS.md, MEMORY.md and CLAUDE.md are exempt at any depth, because /wrap writes them and runs its own Skeptic review; a conductor hand-edit to them outside /wrap is unguarded by design. It fails open on any error, and AE_SHIPPABLE_GUARD_DISABLE=1 turns it off.

Why every engineer gets its own worktree

Worktree isolation is mandatory for every concurrent engineer, qa-engineer and release-orchestrator spawn. The main worktree is reserved for the conductor's branch and its untracked scaffolding under .agentic/. A subagent running in the main worktree can stage and commit those conductor-side files into its own commit, and two parallel spawns sharing one working tree contaminate each other's commits. Neither failure breaks a test. It shows up later, as a reviewer asking why one of the conductor's .agentic/ state files is in the PR.

There is no in-place exception. A Trivial change runs in an isolated worktree too. It keeps its lightweight posture, with no Skeptic and no brief; only the place where the edit happens moves off the primary checkout.

Branched from origin, and what that implies

Because each worktree branches from the base branch on origin, a file that is missing from that tree is missing from the worktree too. Gitignored and untracked paths are the common case: a planning doc under docs/planning/, a local design folder, a scratch directory. A subagent that cannot read a cited path, and is not told so, will sometimes invent the content rather than stop. So before citing such a path in a brief, the conductor checks that it is absent from origin with git ls-tree, and restates the text in the brief instead, naming which copy is authoritative.

On Claude Code two more hooks guard the boundary from the engineer's side. enforce-worktree-read.py denies a worktree-isolated subagent's Read that reaches back into the primary checkout instead of its own worktree. enforce-worktree-write.py does the same for writes, which catches a subagent that has silently fallen back to the primary checkout: it still looks like a subagent, so the shippable-edit guard would let it through. Both fail open and have their own kill switches.

Fresh engineers for fix passes

When a Skeptic, QA or CI finding needs a fix, it goes to a new implementer, never back to the finished one. Resuming the old agent carries its whole transcript into the fix pass, which is how fix passes die of context exhaustion. The new engineer gets the findings verbatim, the pushed branch and its head SHA, after the conductor has confirmed the work is actually on origin.

Cleaning up without losing work

When an engineer's work is complete, meaning its review gates have returned and it will get no further work, the conductor retires the checkout with ds-retire-carrier. It removes the checkout only, never the branch, and only when the checkout is unlocked, clean, has no git operation in progress, holds no protected ignored content, and every commit it holds stays reachable afterwards from a local branch, a reflog or a live origin branch. Otherwise it records a hold with an owner, a reason and a revisit event. Deleting the branch is a separate step with its own proof, and no cleanup step deletes a branch just because a PR merged.

Why it matters

Agents that share a working tree share their mistakes. Giving every engineer its own worktree from origin, and keeping the conductor out of shippable files, means each PR contains one engineer's work and nothing else, and leaves the conductor free to keep talking to you while that work runs.
